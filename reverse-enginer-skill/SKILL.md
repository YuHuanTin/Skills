# 文档编写

## 层级与命名
- 在第一个章节之前写全局对照表，用三个表格记录原类、方法、字段名和重命名后的名字，后续文档编写均使用替换之后的名字，如果类命名为新名字，方法、字段依旧使用原类名，尽可能不写 other 注释
  ```
  |class name|new name|other|
  |---|---|---|
  |aaa|A||

  |func name|new name|other|
  |---|---|---|
  |aaa.f|F||

  |field name|new name|other|
  |---|---|---|
  |aaa.i0|iType||
  ```
- `#` 文档主题；`##` 大章节，按模块/阶段/步骤划分；`###` 子章节
- 长分析文档用编号章节(`## 1. xxx` / `### 1.1 xxx`)，便于交叉引用(见 xxx 章节)
- 子章节直接用函数名、或步骤名作标题(`### IO_8001200C`、`### unpackData`、`### 刷入 img`)

## 小节布局
1. 一句话简述功能/目的/步骤("初始化"、"移动，主要逻辑"、"生成密钥")
2. 贴真实代码/命令/配置，反编译输出原样保留(含 v4/sub_xxx 等符号)
3. 必要时补一句分析或主次区分(如"重点在驱动交互，其余均为负责输入的逻辑")
4. 涉及调用链时画调用栈图

## 代码与命令
- 算法/流程用伪代码块或真实代码，函数名英文、描述中文
- 关键地址、偏移、patch 命令直接给出(VA 0x1400026BD，RVA 0x26BD；`eq ShadowGateSys+0x26bd c483489090909090`)
- 命令连同输出一起贴，保留提示符(`>` / `#` / `$`)

## 推测与证据
- 推测性结论明确标注("猜测"、"可能"、"存疑")，结合实际代码/字符串/符号论证
- 分析技巧记录在文档中(如难分析的 call 先 nop 掉看整体流程、用花指令魔数定位泄漏点)
- 重要结论用 **加粗** 或 blockquote `>` 强调；废弃思路用 ~~删除线~~

## 维护
- 分析完成后总是编写或修改关键总结 markdown
- 若文档已存在，核对与最新结论是否一致，不符则修正
- 长文档章节较多时开头写一段导言，说明章节顺序与阅读路径

# 通用规则

在确定的情况下函数内容的情况下可以对函数重新命名，在分析大函数时，可对其中的小函数进行重命名

在确定的情况下可简短的重命名函数内的变量、全局变量名

# 重构代码文件

遇到重构代码要求时，对指定代码文件进行可读化重写、可重命名变量名、字段名、函数名

对重命名后的函数在上方进行注释，内含有原来方法名、函数简单功能描述介绍

文件开头写入所有描述信息、总结信息，最后不要输出内容到对话输出中
